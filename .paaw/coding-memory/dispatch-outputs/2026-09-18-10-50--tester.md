## 【目標 2】「0✓ 0✗ 0⋯」根因 — 已查明，並順手修了 package.json

**根因：Node v25 的 `node --test` 非 TTY 下也只輸出 spec reporter，輸出裡完全沒有 TAP 行；IDE 的 npm-script 計數 parser 在裡面找不到任何可數的行 → 全部記 0。**

證據鏈（每步都有實證）：

1. **測試其實有跑且全過**：`RUN-20260918-004.json` 的 `outputTail` 結尾明確有 `ℹ tests 26 / ℹ pass 26 / ℹ fail 0`，`verify-last.json` 也擷取到同樣輸出 —— 但 `summary` 記 `0/0/0`。`status: "pass"` 是靠 exit code 0 判的，計數則是 0。
2. **不是偶發**：RUN-001 ~ 004 四個 run 全部 `0/0/0` → 系統性。
3. **實測重現**：模擬 IDE 環境（`FORCE_COLOR=1 npm test` pipe）→ stdout 全是 spec 格式（`✔`/`ℹ pass`），`grep -cE '^(ok |not ok |# pass)'` = **0 行 TAP**。Node 新版已把預設 reporter 換成 spec（舊版 pipe 時會出 TAP，這正是「以前偵測得到、現在 0」的版本行為變化點）。
4. **不是 gates.json 設定問題**：`.paaw/gates.json` 存在（commit 0efcf9b），只調門檻等級（test=唯一 hard gate），**沒有**任何輸出解析設定 —— 計數邏輯是 IDE 內建 parser，不隨專案設定。
5. **次要因素**：IDE 注入 `FORCE_COLOR`（log 有 `NO_COLOR ignored` 警告）導致輸出帶 ANSI 色碼，但非根因 —— `ℹ pass 26` 就算帶色碼仍可被 substring 匹配，parser 是根本不看 spec 格式。

**修復**（屬授權範圍的 script 指令問題）：`package.json` test script 釘死 TAP reporter —

```json
"test": "node --test --test-reporter=tap --test-reporter-destination=stdout \"tests/**/*.test.mjs\""
```

修後實測（`FORCE_COLOR=1` 環境下）：exit 0、stdout 出現 **`# tests 26 / # pass 26 / # fail 0`**、`ok` 15 行、`not ok` 0 行、**0 個 ANSI 碼**（TAP 不吃 FORCE_COLOR，輸出乾淨）。glob 改引號包起來交給 Node 自行展開，`**` 不再依賴 shell 行為。
